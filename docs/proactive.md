# 通用主动任务与通知

每个成功结束的用户 Turn 都在后台进入一次任务提取队列。主动推送开启时，端侧模型读取该轮 query、已确认记忆和现有任务，静默判断是否应创建、更新、取消任务；普通问答输出 `none`。提取结果必须包含 query 原文证据，时间和重复规则也必须能在 query 或已确认记忆中找到依据。每轮最多生成一条任务，已处理的 Turn 不重复提取。模型暂时失败时保留队列并延后 5 分钟，继续处理后续对话；iOS 在进程可运行时自动重试，其他端在下次启动或下一轮对话后重试。每批最多处理 5 轮，批次之间释放执行锁。桌面端仅使用本机模型地址执行提取，iOS 和 Android 使用已导入的端侧模型。

主动发现不依赖新 Turn。用户可在每台设备独立开启主动推送，选择 15 分钟、30 分钟、1 小时或 3 小时的后台发现间隔；默认关闭、默认间隔 30 分钟。Rust 持久化最近扫描时间，避免重复调用端侧模型。关闭时不生成新任务、不运行到点任务，也不投递已准备的通知。扫描读取已有记忆、已连接查询工具的用途及参数模式，泛化推理有明确帮助价值的未来任务。到点后查询实时条件，仅在建议仍有价值时推送。提取器拒绝保存模型虚构的工具名；没有稳定检查时间或可用实时工具时不创建任务。同一记忆与检查时间不会反复生成任务，用户删除后也会记住该来源已被拒绝。

Turn 触发与后台扫描都只负责建立未来的检查计划，不负责感知未来的天气。天气突然变化时立即触发的事件订阅仍未实现。

每条任务保存稳定 ID、名称、执行指令、记忆检索关键词、允许调用的查询工具名、推送前至少一个必须成功调用的工具名，以及一次性事件时间或当地每周重复时间、提前启动分钟数和截止分钟数。用户通过“主动任务”页面查看、停用或删除自动生成的任务。饭点、通勤只是可迁移的旧任务，不再是调度器允许的仅有场景。

任务保存在本地 SQLite `proactive_tasks`，已提取 Turn 保存在 `proactive_planned_turns`，失败提取的重试时间保存在 `proactive_planner_retries`。升级时将历史已完成 Turn 标记为已处理，避免追溯生成旧任务。启动时会把旧 `proactive_rules` 中的饭点和通勤配置一次性迁移，保留原时间与开启状态。运行记录保存在 `proactive_runs`，以任务 ID 和事件时间去重。修改或删除任务会使其未投递结果失效。

App 启动、设置变化或定时器唤醒时刷新设备时区偏移。App 读取所有任务的下一次执行时间、失败重试时间和结果过期时间，等待最近的一个时间点；没有待执行任务时停止等待。到点后 Rust 在事务中领取任务并规划该任务下一次运行。任务失败后在 5 分钟后、截止前可重新领取；App 调度出错则在 1 分钟后重试。

领取任务后，Harness 启动独立、静默的多步 Agent Loop。它按该任务的关键词检索有效记忆，只披露任务明确允许的工具，并把名称、指令和时间窗口传给模型。MCP 工具仍经过原有审批流程。最多执行 5 步，截止时间到达即停止。模型输出 `push/skip`；配置了必需工具时，至少一个工具成功返回才允许推送。没有成功的实时工具结果时，通知文案只能使用任务名称和通用的打开 App 建议，避免编造天气、商家、价格或时效。后台不会下单、付款或叫车。

结果先保存为 `ready`。App 检查通知权限并提交系统通知，成功后才标记为 `delivered`。iOS 在首次自动创建启用任务时申请通知权限，桌面 JVM 使用系统托盘通知。推送动作固定为打开 App。

## 手机退出后的计划提醒

启用主动推送后，iOS 将固定一次性/每周时间写入系统通知触发器；Android 将提醒持久化并交给 AlarmManager，重启、时区/时钟变化及升级后恢复。停用、删除任务或关闭总开关会移除对应排程。提醒时间为事件时间减提前分钟数，跨日、跨周正确换算；每周按当地时间重复。启用任务生成的排程总量限制为 64，超限明确报错。

这类通知只展示任务名称和“请打开 App 查看并处理；尚未检查实时条件”。它不运行模型、不查询天气或其他实时条件；原有 Agent 仍在进程可运行时提供实时建议，两条通知链路目前可能分别展示提醒和建议。要保证退出 App 后仍完成实时判断，需要继续接入服务端调度、远程推送及常驻推理能力，尚未实现。

通知权限在 UI 中显示；Android 未获精确闹钟权限时使用非精确排程并提示可能延迟，可从设置进入系统授权。系统通知权限、专注模式、省电策略和 Android 强行停止仍影响实际送达，不能承诺无条件准时。Mac 可通过 `--worker` 常驻运行原有主动任务与自动接单，详见[跨设备执行](cross_device_execution.md)。

## 当前边界

- 固定计划提醒已交给手机系统排程；主动发现、实时检查与端侧推理仍依赖可运行的 App 或 Mac worker。
- 后台发现间隔由本设备配置；固定行程前的实时条件检查由任务本身的唤醒时间触发。App 休眠时扫描和本地模型运行可能延迟。
- 工程尚无内置天气、餐厅、配送或打车数据源。需要实时依据的任务应配置相应查询工具和必需工具；工具未连接时会跳过。
- 支持一次性时间和按当地时间每周重复，重复规则支持任意星期组合。明确给出的 `yyyy-MM-dd HH:mm[:ss]` 由代码校验并按设备时区转换，模型无需计算 Unix 时间。无实时查询条件的固定提醒允许不提前提醒；实时检查任务仍要求提前执行窗口。地点或外部事件触发器尚未接入。设备时区偏移在启动、设置改变或下一次定时器唤醒时刷新。
- 查询工具名称由模型从当前 MCP 工具清单中选择，并限制为查询类名称；工具用途仍需在 MCP 集成处核验，外部调用受 MCP 审批约束。
- 端侧模型输出的相对日期会校验当天、明天和后天；任意自然语言日期、中文时分与模型输出时间的一致性尚需更完整的解析器。
- Android/iOS 的系统排程已接入代码；权限撤销、重启、夏令时、挂起及强行停止后的行为仍需设备端到端验收。

2026-10-07 已在新建 iOS 27 模拟器验收一次性计划：允许通知、终止 App 后，SpringBoard 实际显示提醒，测试通过且无跳过。复现步骤见[本机验收记录](cross_device_execution.md#2026-10-07-本机验收记录)。这一结果不覆盖真机、每周重复、夏令时或系统权限撤销场景。

## 真机验收修复

后台计划提取启用结构化输出，MLX 对 JSON Schema 进行约束并关闭该后台请求的思考模式；普通聊天的思考与流式输出保留。原文证据与显式日期限定为输入中的实际文本；明确给出日期并请求提醒时，不允许模型用 `none` 丢弃该请求。共享模型优先级防止记忆提取在计划批次内插入，单条失败不会阻塞后续任务，也不会隐藏已保存的任务。

iOS 页面读取系统实际待投递通知数量，并在排程集合与任务不一致时报错。物理设备复验结果另见 `scripts/acceptance/results-2026-10-09.json`，首次失败记录保留。

2026-10-09 修复后，同一台 iPhone 17 Pro Max / iOS 27.0.1 完成真机全流程，445.223 秒通过：真实对话创建一次性任务；停用后系统待排程从 1 变为 0，重新启用恢复为 1；终止 App 后 20:53 实际显示这条新提醒的系统横幅；点击横幅回到 App；删除已触发的测试任务并保留原先开启的总开关。首次失败结果没有覆盖，修复和最终证据另记于验收 JSON 的 `ios_proactive_fix`。

这一结果只覆盖已授权通知、亮屏解锁状态的一次性固定提醒。每周重复、夏令时/时区变化、权限撤销、专注模式、锁屏以及删除未来待排程任务仍待分别验收。退出 App 后执行模型或实时查询、远程 APNs 推送仍未实现。
