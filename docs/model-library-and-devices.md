# 模型库与跨设备使用

## 选择端侧模型

手机打开“设置 → 端侧模型”，Mac 打开设置中的“模型库”。先选择推理引擎，再浏览对应的 Hugging Face 在线列表：MLX 使用 `mlx-community` 组织，llama.cpp 和 Mac Ollama 使用 GGUF 仓库。列表按下载量排序，支持搜索和分页，并显示仓库、下载量、喜欢数、更新时间和模型页入口。已下载模型单独显示，刷新列表不会触发重新下载。

浏览和“查看文件”只读取元数据。GGUF 仓库展开后选择具体量化文件；MLX 展开后确认文件总大小、内存估算和架构适配情况。只有点击“下载”才获取权重，下载完成不自动切换当前模型。之后点击“使用此模型”才启用，当前模型显示禁用的“使用中”。MLX 页已移除旧的独立下载按钮；GGUF 保留手动文件导入。

模型库切换保留其他模型文件，下载失败不修改当前选择。离线时已下载模型仍可选用，在线列表失败显示错误并可刷新。下面是原有模型的门槛示例，在线列表不局限于这三个模型。

| 模型 | iOS | Android | Mac 当前接入 | 建议总内存 |
| --- | --- | --- | --- | --- |
| Qwen3.5 4B MLX 4bit | MLX | 不支持 | 尚未接入 MLX | 8 GB |
| Qwen3.5 4B GGUF Q8 | llama.cpp | llama.cpp | Ollama | 12 GB |
| Qwen3 0.6B GGUF Q8 | llama.cpp | llama.cpp | Ollama | 4 GB |

这些门槛是应用的保守估算，不是模型发布方的性能保证。检查涵盖系统版本、已接入引擎、CPU 架构、总内存和存储。未知内存或存储不判定为支持。下载要求剩余空间至少为模型文件大小两倍再加 1 GB，用于暂存；已安装模型的切换不再要求下载空间。iOS 要求 17+，Android 要求 API 26+；Mac 模型库按 macOS 14+ 检查。实际速度和长上下文可用性仍需在目标设备验证。

iOS/Android GGUF 使用解析时固定的仓库版本、精确文件大小和 SHA256；iOS MLX 从 Hugging Face 文件元数据生成固定版本的逐文件清单，LFS 权重按 SHA256 校验，小文件按 Git blob ID 校验。下载暂存完成并校验后才安装。Mac 通过本机 Ollama `/api/pull` 下载 Hugging Face GGUF，下载和完整性由 Ollama 管理，其仓库文件标签跟随上游版本。Mac 使用模型库前需要本机 Ollama 已运行，并在模型连接中保存本机地址。自定义远端模型接口不执行本机下载。

当前模型输入仅支持文本。轻量 0.6B 模型用于低内存设备的基础问答，复杂理解能力有限。下载期间保持 App 前台；当前没有断点续传或 App 退出后的下载承诺。Android 代码与共享 UI 已接入，Android SDK/真机尚待验收。

模型来源：[Qwen3.5 MLX 4bit](https://huggingface.co/mlx-community/Qwen3.5-4B-MLX-4bit)、[Unsloth Qwen3.5 GGUF](https://huggingface.co/unsloth/Qwen3.5-4B-GGUF)、[Qwen3 0.6B GGUF](https://huggingface.co/Qwen/Qwen3-0.6B-GGUF)。Mac 的 Hugging Face 模型命名按[官方 Ollama 集成说明](https://huggingface.co/docs/hub/en/ollama)。

## 配对自己的手机和 Mac

A2A 是任务通信协议，普通用户不用理解或配置协议字段。自己的设备通过“跨设备执行”配对，任务提交、追问、取消和结果传递由应用处理。

1. 管理员部署一个设备服务，提供 HTTPS 地址和首台设备令牌。首台 Mac 在“跨设备执行 → 高级设置”填写令牌、服务地址和设备名称，保存连接。
2. 在已连接的 Mac 中点击“生成 10 分钟配对码”。界面同时显示服务地址和配对码，不再需要手填新设备 ID。
3. 手机打开“设置 → 跨设备执行”，填写同一服务地址、手机名称和配对码，点击“使用配对码连接”。希望手机执行其他设备发送的任务时，勾选接单开关并保存。
4. 配对后设备自动发现；已手动停用的设备仍保留停用状态。无需在第三方 A2A 页面重复添加自己的设备。
5. 在对话中说“请把任务「计算17+25，只输出数字」委托给 Acceptance Mac”。确认发送后，任务进度和结果回到当前对话，也可在“任务”页面查看。

手机目前按前台接单能力提示；退出 App 后自动执行与推送不属于此次验收范围。其他设备也要在线且允许接单。HTTPS 服务不是 A2A Agent Card；两种地址不能混填。

## 普通问答与委托

“柿子能和螃蟹一起吃吗”等知识问答默认由当前设备回答。仅当当前请求明确表达远端执行意图（例如“委托给 Mac”“在 Mac 上执行”）时，才开放设备发现、路由和委托工具。模型自己声明“需要某种远端能力”不能获得委托权限；历史委托也不能授权下一轮问答。

这次修复采用保守规则：明确委托才执行跨设备操作。缺少本机工具时，助理可以说明限制，用户再指定远端执行。目前不使用模型自报的能力需求自动委托。

## 第三方智能体

只有连接独立的第三方 Agent 才使用“跨设备执行 → 高级设置 → 远端 Agent（A2A）”。填写对方提供的 Agent Card 地址，按需要保存 Bearer 令牌并启用。自己的手机、Mac 使用配对流程即可。
