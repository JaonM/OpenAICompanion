# 跨端记忆同步

中期和长期记忆通过自建 HTTPS 服务在同一用户的设备间合并。短期对话上下文、会话轨迹、主动任务、MCP/OAuth 凭据和模型文件不参与同步。服务端保存记忆正文，因此部署者必须保护数据库和备份；TLS 只保护传输。

## 启动服务

准备受设备信任的 TLS 证书和私钥，为每个用户生成高熵随机令牌。`MEMORY_SYNC_TOKENS` 是“令牌 → 用户 ID”的 JSON 映射，例如 `{"<随机令牌>":"user-1"}`。将其放在受限权限的进程环境文件中，不要提交到仓库或写入命令行参数。启动服务时通过进程管理器注入环境变量：

```sh
python3 scripts/memory_sync_server.py \
  --db /secure/path/memory-sync.sqlite \
  --cert /secure/path/fullchain.pem --key /secure/path/privkey.pem \
  --host 0.0.0.0 --port 9443
```

服务接口为 `https://主机:9443/v1/memories/sync`。每台设备在设置中填入同一地址和令牌，保存后立即同步。记忆新增、更正、归档或删除时，SQLite 触发器在同一事务中递增持久化待同步版本；提交通知通过 UniFFI 唤醒三端共用的同步 worker，不再依赖对话结束后等待 15 秒。上传前读取版本号和快照，HTTPS 交换及本地合并都成功后，仅确认该次版本；上传期间的新写入保留待同步状态并继续发送。远端合并不递增本地待同步版本，避免回传循环。

失败保留待同步状态，App 运行时按 1、2、4、8、16、32、60 秒退避重试，之后间隔上限 60 秒；新写入不会绕过失败退避。启动时立即交换，恢复退出前未确认的修改；运行期间每 15 分钟交换以拉取其他设备变更，也支持手动同步。手机 App 被挂起或退出期间不会执行 worker，恢复执行或再次启动后继续；服务端暂无变更推送。清空地址可停用该设备的同步。

服务按令牌映射的用户 ID 隔离记录，按记忆 ID、修订时间和设备 ID 合并；删除记录以墓碑传播，避免其他设备在下一轮同步时恢复。端侧在同步前扫描本地记忆表的变化，因此端侧模型和用户修改都可被同步。同步使用 version=2 分页协议：每批最多 256 条，上传批次与下载页按 UTF-8 字节控制在 512 KiB 内，HTTP 硬上限为 4 MiB。服务端按变更序号返回页；客户端逐页持久化后才推进游标，整轮成功后才确认本地待同步版本。每轮从游标 0 开始，因此中断重试、客户端重启和服务端备份恢复都能通过幂等重放恢复，不存在 10,000 条总量上限。当前本地导出仍扫描完整快照，大数据量下后续可优化为持久化增量上传。墓碑持续保留；在引入设备确认水位之前不自动回收，以免离线设备恢复已删除的记忆。设备时钟应保持同步；同一记忆的并发修改使用修订时间和设备 ID 确定性决胜，暂不提供冲突审阅。令牌轮换、端到端加密和设备撤销仍需部署与产品层扩展。

升级时先部署新版服务，再升级客户端。新版服务兼容旧版完整快照请求；旧协议若会产生超容量响应，将在提交前整体回滚并返回 413。新版客户端遇到旧版服务会明确报错，不确认待同步版本。

Android 令牌存入 Keystore 加密偏好，iOS 和 macOS 存入 Keychain。凭据按同步服务地址隔离；仅地址未变时允许留空令牌复用，更换服务必须提供新令牌。旧版本的令牌首次使用时迁移到当前地址对应的安全存储；macOS 迁移成功后移除 Preferences 中的旧值。配置修改和同步共用互斥锁，避免请求混用新旧地址与凭据。
